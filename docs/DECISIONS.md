# Архитектурные решения

## SDK и финансовый расчёт

Закреплён SDK 8.0.428. Расчёт получает событие и контракт аргументами. Повторный расчёт по тем же данным даёт одинаковые начисления. Четыре знака у долей, `decimal` для квот и целые копейки в `long` позволяют сверить сумму долей с округлённым общим начислением.

## CSV и частичные ошибки

Один UTF-8 файл с каноническим заголовком и одной физической строкой на событие. Допускаются BOM, LF и CRLF, кавычки вокруг отдельных полей и удвоенные кавычки. Многострочные значения, сломанные кавычки, неверная кодировка, длинная физическая строка и неверный заголовок делают файл структурно непригодным. API возвращает 400, превышение 128 МиБ — 413. Ограничение физической строки составляет 1024 символа, поля Platform — 64 символа, Country — две заглавные латинские буквы.

Прочитанные строки данных, в том числе пустые, входят в total. Неверные значения, неверное количество столбцов и незарегистрированные TrackId входят в invalid. Из подходящих строк первая по порядку с каждым EventId считается кандидатом на вставку. Повторы в одном файле и события, уже сохранённые другими импортами, входят в duplicate, даже если поля расходятся. Для завершённого импорта `total = inserted + duplicate + invalid`. Структурный дефект откатывает весь импорт. Preview использует временную таблицу и откатывает транзакцию. Он показывает прогноз статистики на момент запроса, а примеры ограничены 20 ошибками парсинга. Конкурентные операции могут изменить окончательную статистику.

## Идемпотентность, состояния и атомарность

SHA-256 вычисляется от исходных байтов. Файлы с разными окончаниями строк имеют разные SHA-256, а общий PK EventId защищает usage при любом содержимом. При совпадении SHA-256 уникальный индекс создаёт одну общую запись `Pending`. Обработка захватывает её через `SELECT ... FOR UPDATE`. Параллельный вызов ждёт освобождения блокировки и возвращает результат завершённого импорта или повторяет попытку после ошибки.

Переход `Processing` фиксируется внутри транзакции работы и с других подключений обычно виден предыдущий `Pending` или `Failed`. `Completed`, события и начисления фиксируются одним коммитом. При обрабатываемой ошибке откат к savepoint удаляет результаты работы, и та же транзакция фиксирует `Failed` с нулевыми счётчиками. Счётчики Failed не описывают частичный результат. Отмена, разрыв соединения или остановка процесса могут оставить предыдущий статус. В обоих случаях повтор тех же байтов продолжает работу с тем же ID. При потерянном подтверждении коммита повтор вернёт сохранённый результат, если сервер успел зафиксировать транзакцию. Исправление невалидных строк либо изменение каталога после `Completed` не переоткрывает завершённый импорт. Для повторной подачи исключённых строк сформируйте отдельный файл.

Применимую версию договора определяет дата usage и снимок каталога на момент сопоставления. Начисления создаются только для новых событий с применимой версией. Существующие записи и начисления сохраняют исходные данные при повторах. Период хранится рядом с доменным контрактом в persistence-модели. Сумму долей валидирует домен при записи через API и при расчёте. Прямые записи SQL должны соблюдать этот же инвариант.

## Генератор

Поля выбираются через `Random(seed)` в .NET 8. EventId однозначно кодирует seed и индекс, TrackId выбирается из общего синтетического каталога на 1000 идентификаторов. Строки записываются по одной через буфер `StreamWriter`.
